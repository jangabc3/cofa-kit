# 합의문

`INTERVIEW.md`와 README를 바탕으로 `AGREEMENT.md`를 쓴다. 근거가 없는 내용은 지어내지 말고 "미확인"으로 둔다.

README가 정한 과제의 전제(웹 서비스로 만들 것, 제공된 OpenAI API 등)는 그대로 둔다. 담당자의 조건은 그 전제를 빼는 근거가 아니라 **쓰는 방식을 정하는 조건**으로 읽는다. 예: "AI에 보낼 때도 가려야 한다" → AI를 쓰지 않는다(X), 가린 뒤에 보낸다(O).

## AGREEMENT.md 형식
```
# 합의문 (v1, 시각)

## 이해한 문제
누가, 언제, 무엇 때문에 곤란한가. 2~3문장.

## 원인
지금 방식에서 시간이 새거나 실수가 나는 지점.

## 쓰는 사람과 장면
누가 어떤 순서로 쓰는가.

## 성공 기준
| 기준 | 지금 | 목표 | 확인 방법 |
(숫자나 관찰 가능한 행동으로. 예: "답변 녹음 후 30초 안에 피드백이 보인다")

## 이번에 만들 것
1. (가장 중요한 것 하나가 맨 위)

## 이번에 만들지 않을 것과 이유
- (요청은 있었지만 시간, 위험, 우선순위 때문에 뺀 것)

## 지켜야 할 조건
| 조건 | 예외·단서 ("다만", "~한 경우에만") | 출처 |
| (인터뷰에서 나온 숨은 조건 전부) | (있으면 그대로, 모르면 "미확인 → 질문") | Q3 |

## 미확인
- (아직 못 물은 것. 가정으로 진행하면 그 가정도 적는다)
```

예외·단서가 "미확인"인 조건 중 결과를 바꿀 만한 것은 확인 메시지의 질문으로 넣는다. 단서 하나로 결론이 뒤집히는 경우가 많다.

## 담당자 확인 메시지
합의문 아래에, 담당자에게 그대로 보낼 짧은 메시지를 쓴다.
- 개발 용어 없이 현업의 말로 쓴다.
- 만들 것 3줄 이내, 만들지 않을 것과 이유 2줄 이내, 확인 질문 1~2개.

담당자 답을 받으면 합의문 버전을 올리고(v2) 바뀐 부분을 `DECISIONS.md`에 남긴다.
