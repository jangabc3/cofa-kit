# 담당자 인터뷰 준비와 기록

담당자는 막연한 질문에는 되묻고, 업무의 구체적인 대상을 짚은 질문에만 숨은 조건을 말해 준다. 이 스킬은 그런 질문을 뽑는다.

## 0. 제출 요구 확인
README에서 필수 제출 파일, 문서 이름·위치, 실행 방법, 금지 사항을 찾아 `INTERVIEW.md` 맨 위에 "제출 요구" 목록으로 적는다. 없으면 "README에 별도 지정 없음"이라고 적는다. 이후 모든 문서는 이 목록에 맞춘다.

## 1. 자료 훑기 (아직 아무것도 만들지 않는다)
- README에서 정해지지 않은 단어(기간, 기준, 대상, 받는 사람, 형식, 분량, "잘", "편하게" 같은 말)를 찾는다.
- 자료 파일은 앞부분과 표본만 본다. 열 이름, 값의 종류, 빈칸, 중복, 이상한 값, 시각 형식, 단위, 비고란을 확인한다.
- 사용자가 누구고 언제, 어디서, 어떤 순서로 쓰는지 아직 모르는 것을 적는다.

## 2. 질문 후보 쓰기
`INTERVIEW.md` 맨 위에 우선순위 순으로 적는다. 한 질문에는 대상 하나만 넣는다.

좋은 질문의 모양: **대상 + 구체 상황 + 열린 질문**
- "선수가 연습 답변을 다시 볼 때, 주로 무엇을 확인하나요?"
- "`state` 열에 PM 이 있는데, 이 시간은 가동률 계산에서 어떻게 보나요?"

피할 질문: "뭘 만들면 되나요?", "주의할 점 있나요?", "AI로 자동화하면 어떨까요?"(해법 단어는 초반에 쓰지 않는다)

묻는 순서:
1. 최근의 구체적인 사례 하나 ("지난번에 이 일을 할 때 어떻게 했나요?")
2. 지금의 임시방편 ("지금은 무엇으로, 몇 분 걸려서 하나요?")
3. 숫자 (빈도, 시간, 기준값, 목표)
4. 사람 (누가 쓰고, 누가 보고, 누가 유지하나)
5. 경계 조건 (예외, 제외 대상, 시간 경계, 이번 범위가 아닌 것)

질문은 8~12개로 하고, 자료에서 발견한 이상한 점은 반드시 하나씩 질문으로 바꾼다.
담당자가 규칙을 말하면 그 규칙의 **예외**를 묻는 꼬리 질문을 하나 추천한다. 예: "PM 중인 장비는 뺀다" → "PM이 끝난 직후 알람도 빼나요?" 단서 하나로 결과가 뒤집히는 경우가 많다.

## 3. 답 기록
사용자가 담당자의 답을 붙여 넣으면 `INTERVIEW.md` 아래에 쌓는다.

```
## Q3. (질문)
- 답: (담당자 말 요약, 숫자와 고유명사는 그대로)
- 조건: (이 답에서 나온 지켜야 할 규칙, 없으면 "사정만 들음")
- 다음 질문: (이 답 때문에 새로 생긴 질문)
```

기록한 뒤에는 아직 열리지 않은 질문 중 다음으로 물을 것을 하나만 추천한다.
