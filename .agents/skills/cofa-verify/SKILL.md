# 검증

"된 것 같다"는 말 대신 증거를 남긴다. 실행하지 않은 확인은 통과로 적지 않는다.

## 먼저 남은 시간을 본다 (`.cofa/START`, 없으면 사용자에게 묻기)
- **남은 시간이 45분 이하면 이것만** (사용자가 남은 시간을 말해 주면 그 값을 쓴다): ① 합의문의 핵심 조건 3개 확인 ② 이상 입력 3개(잘못된 파일, 빠진 기록, 극단값) ③ 위험 실험 1개 ④ 사용자가 눌러 볼 순서. 나머지는 "아직 확인 못 한 것"에 적는다.
- 시간이 더 있으면 아래 전체를 한다.
- 만들 때 이미 만든 테스트와 확인은 다시 만들지 말고 결과만 모은다.

## 순서
1. `PLAN.md`의 기능 요구사항(FR-1, FR-2…)과 `AGREEMENT.md`의 성공 기준·조건을 하나씩 목록으로 만든다. FR마다 적힌 확인 방법을 먼저 쓴다.
2. 각각에 대해 가장 싼 확인 방법을 정한다.
   - 계산과 규칙: 작은 테스트나 스크립트. 값 하나는 손으로 계산한 값과 비교한다.
   - API와 서버: `curl`로 요청해 응답 확인. 잘못된 입력과 빈 입력도 한 번씩.
   - LLM 기능: 정상 입력 1개, 이상한 입력 1개. LLM이 실패할 때 대체 동작이 나오는지.
   - 화면: 사용자가 Browser 미리보기에서 눌러 볼 순서를 3~5단계로 적어 준다. "처음 보는 사람" 점검(5초 안에 할 일을 아는지, 주요 버튼이 하나인지, 빈 입력·로딩·오류 안내가 나오는지)도 한 줄로 넣는다.
3. 실행하고 결과를 기록한다. 실패하면 고치기 전에 원인을 한 줄로 적는다.

## 세 가지 확인 (계산·필터·판정이 있는 기능)
- **중간값과 근거**: 결과만 보지 말고 단계마다 남은 건수와 예시 행을 보여 준다. 예: "전체 312행 → 중복 3건 제거 → PM 장비 12건 제외 → 297건 (제외 예: L100742 PH-03 PM)". 어느 단계에서 틀렸는지 바로 보이게 한다.
- **다른 방법으로 검산**: 핵심 숫자 하나는 다른 경로로 다시 구해 같은지 본다. 예: 합계를 코드와 별도 한 줄 스크립트로 각각 계산, 건수를 그룹별 합으로 다시 세기.
- **함정 테스트**: 합의문의 조건마다 "이 조건을 어기면 결과가 달라지는" 작은 예시를 하나 만든다. 조건을 지킨 결과와 어긴 결과가 다르면 조건이 실제로 반영됐다는 증거다. 같으면 조건이 코드에 들어가지 않은 것이다.
  예: "원인 미확정" 예시 → 초안에 단정 표현이 없어야 함 / 설비명이 든 예시 → AI로 보내는 내용에 설비명이 없어야 함.

## 이상 입력 표 (입력마다)
사용자가 넣는 값(파일, 숫자, 날짜, 선택지)마다 아래 경우를 하나씩 실제로 넣어 보고, 화면에 무엇이 나오는지 적는다. 막는 코드가 없으면 최소한으로 막고 안내 문구를 넣는다.
| 입력 | 경우 | 기대 동작 | 실제 결과 | 확인한 테스트·명령 |
| CSV 파일 | 형식이 틀림(열 없음, 글자 깨짐) | "___ 열이 없습니다" 안내, 저장 안 함 | | tests/… |
| CSV 파일 | 일부 행·사람 기록 누락 | 빠진 것을 목록으로 알리고 나머지로 진행(또는 중단) | | |
| 숫자 값 | 0, 음수, 아주 작음, 아주 큼 | 범위 안내 | | |
| 날짜·시간 | 순서가 뒤집힘, 말이 안 되는 값 | 안내 | | |
| AI 응답 | 실패, 형식 틀림 | 대체 동작 | | |
테스트는 `tests/` 폴더에 작게 만들고, 이름에 경우가 드러나게 짓는다 (예: `test_value_zero`).

## 위험 지점 실험 하나
결과 품질이 깨질 위험이 가장 큰 곳을 하나 고르고, AI의 설명이 아니라 **실험**으로 확인한다.
- 예: 작은 데이터에서 "모든 경우를 다 따져 본 답"과 내 방식의 답을 비교 / 무작위 입력 20개로 규칙 위반이 있는지 검사 / 경계값(1, 0, 아주 큰 값)에서 결과 확인
- 결과를 `VERIFICATION.md`에 숫자로 적는다 (예: "20개 중 18개 같음, 다른 2개는 ___ 때문").

## VERIFICATION.md 형식
```
| # | 확인할 것 (출처) | 방법 | 결과 | 증거 |
| 1 | FR-2 AI 전송 전 내부 정보 가리기 (Q6) | 설비명이 든 예시로 전송 내용 출력 | 통과 | "PH-07" → "노광 공정 장비" |
| 2 | Q2 단정 금지 (함정 테스트) | 원인 미확정 예시 입력 | 통과 | 지킨 결과 "조사 중입니다" / 규칙을 끄면 "원인은 ○○로 확인" |
| 3 | 성공 기준 1: 초안 30분 이내 | 사용자 직접 확인 | 확인 필요 | - |
```

마지막에 "아직 확인 못 한 것"과 "알려진 약점"을 따로 적는다. 숨기지 않는다.
